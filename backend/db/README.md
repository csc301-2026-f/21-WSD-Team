# Database Component: SQLite History Repository

The Database component (`backend.db`) provides local persistence and time-series telemetry storage for the Wise Storage Director (WSD). It acts as the system of record across OS reboots, application restarts, and long-running monitoring sessions.

The database stores incoming telemetry from the OS collection agents (forwarded via CORE), supplies historical activity and access patterns to the optimization algorithms (**ALGO-01** and **ALGO-02**), serves historical charts to the frontend dashboard, persists user preferences, and stores file monitoring subscriptions and file migration records.

---

## 1. How It Works

### Storage Engine and Concurrency
The database uses embedded **SQLite** with Write-Ahead Logging (**WAL** mode). 
- `PRAGMA journal_mode = WAL;`: Allows concurrent reading while writes are in progress. The OS collection agent or CORE background worker can continuously ingest telemetry without blocking UI queries or algorithmic evaluations.
- `PRAGMA foreign_keys = ON;`: Enforces referential integrity across related records (e.g., cascading deletes for device metrics when a device is deregistered).
- Schema auto-initialization: On instantiation, `SQLiteHistoryRepository` reads [`backend/db/schema.sql`](schema.sql) and executes table creation scripts using `CREATE TABLE IF NOT EXISTS` and composite index creation.

```text
 [OS Agent: Linux/Windows]
            │
            ▼ (telemetry snapshot)
     [CORE Service]
            │
            ▼ (plain dicts/dataclasses)
 [SQLiteHistoryRepository] ──writes──► [wsd.db (WAL mode)]
            ▲                                ▲
            │                                │
      (read queries)                   (SQL queries)
            │                                │
    ┌───────┴───────────────────────┐        │
    │                               │        │
[ALGO-01 / ALGO-02]         [Frontend Dashboard]
(Prediction & Placement)    (Charts, Heat & History)
```

### Core Relational Schema
The database maintains eight core tables:

1. **`devices`**: Discovered storage hardware metadata (capacity, free space, mount points, availability, media type).
2. **`device_metrics`**: Time-series physical drive I/O telemetry (read/write bytes per sec, IOPS, latency).
3. **`process_metrics`**: Application-level I/O telemetry with stable composite IDs (`f"{pid}_{start_time_utc}"`) to avoid collision upon OS PID reuse (US-02).
4. **`file_activity`**: High-resolution file-level observation windows (bytes, operations, file size, access gaps).
5. **`file_subscriptions`**: Monitored file and folder paths persisted across system reboots.
6. **`file_move_records`**: Stores migration byte counts (`bytes_total`, `bytes_moved`), execution status, errors and timestamps supplied by callers.
7. **`recommendations`**: Advisory placement proposals generated by algorithms.
8. **`app_settings`**: Key-value store for user configurations, UI themes, and automation flags.

### D4 Telemetry & Prediction Support

#### 1. Spatial Locality & Access Gaps (`read_average_gap`, `write_average_gap`)
Files with frequent non-sequential (random) access benefit significantly from the low random access latency of SSDs. To inform ALGO-01's adaptive workload prediction and spatial scoring:
- `read_average_gap` (`REAL`, nullable): Mean distance in bytes between the start of a read operation and the end of the previous read on the same open file (`0.0` = completely sequential, `None` if unmeasured).
- `write_average_gap` (`REAL`, nullable): Write equivalent metric.
These metrics are stored in `file_activity` and queried by algorithms through `query_file_activity_windows()` and `query_file_heat()`.

#### 2. Query Window Ordering for Prediction (`ORDER BY window_start_utc DESC`)
Machine learning and adaptive prediction models in ALGO-01 require the most recent file activity history (up to the last 60 minutes). When the database contains tens of thousands of observation windows:
- `query_file_activity_windows()` orders results by `window_start_utc DESC LIMIT ?` (default limit `5000`).
- This guarantees that when results are truncated by the safety limit, the algorithm receives the freshest historical windows, rather than stale historical data from days prior.

#### 3. Persistent Monitoring Subscriptions (`file_subscriptions`)
Users or automated policies subscribe specific directories or files for continuous tracking. The repository persists subscription targets with `status IN ('active', 'paused', 'removed')`. Upon system reboot or service startup, CORE calls `list_file_subscriptions(status='active')` to resume OS-level file monitoring hooks without requiring user re-configuration.

#### 4. Migration Records and Incomplete Moves (`file_move_records`)
The repository can record:

- `bytes_total` and cumulative `bytes_moved`.
- Lifecycle status: `pending` → `approved` → `in_progress` → `completed` (or `failed`/`cancelled`).
- `get_incomplete_file_moves()`: Returns unfinished moves (`status IN ('approved', 'in_progress')`). These records survive application restarts.

CORE currently saves an `in_progress` record when a move starts and polls the live move handle for progress. It does not yet persist ongoing progress or completion, restore move handles after restart, or resume a transfer from a saved byte offset.

## 2. Developer Guide

### Setup and Testing
The database component requires Python 3.10+ and standard library SQLite3.

To run the database test suite:

```bash
# Run database contract and repository unit tests
python -m pytest tests/test_db_contract.py -v

# Run file I/O, subscription persistence and move-record tests
python -m pytest tests/test_db_file_io.py -v
```

### Windows File Locking and WAL Test Hygiene
On Windows systems, SQLite WAL mode retains file locks until all connection handles are garbage-collected. To avoid `PermissionError` when deleting temporary databases during testing:
- Tests use pytest's built-in `tmp_path` fixture to isolate database files per test function.
- Repositories are garbage-collected via `gc.collect()` in fixture teardown.

```python
@pytest.fixture
def repo(tmp_path):
    db_file = str(tmp_path / "test_wsd.db")
    repository = SQLiteHistoryRepository(db_path=db_file)
    yield repository
    gc.collect()
```

### Code Structure

The database implementation resides in [`backend/db/`](./):

| File | Purpose |
|---|---|
| [`repository.py`](repository.py) | `SQLiteHistoryRepository` implementation: connection management, parameterized queries, and serialization. |
| [`schema.sql`](schema.sql) | DDL schema: table definitions, column types, default values, foreign key cascades, and composite indexes. |
| [`__init__.py`](__init__.py) | Package initialization exposing `SQLiteHistoryRepository`. |
| [`tests/test_db_contract.py`](../../tests/test_db_contract.py) | Unit tests verifying query contracts, time-bucketing, conflict updates, gap metrics, and edge cases (30 tests). |
| [`tests/test_db_file_io.py`](../../tests/test_db_file_io.py) | Tests for file activity, subscription persistence, move records and incomplete-move queries. |

## 3. Database Schema Reference

### Table: `devices`
Stores recognized block storage devices.
```sql
CREATE TABLE IF NOT EXISTS devices (
    device_id TEXT PRIMARY KEY,
    host_id TEXT NOT NULL,
    display_name TEXT,
    media_type TEXT,            -- 'ssd', 'hdd', or 'unknown'
    capacity_bytes INTEGER,
    free_bytes INTEGER,
    mount_points TEXT,          -- JSON list of mount path strings
    is_available INTEGER NOT NULL DEFAULT 1,
    last_seen_utc TEXT NOT NULL
);
```

### Table: `device_metrics`
Telemetry samples for physical drives.
```sql
CREATE TABLE IF NOT EXISTS device_metrics (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    device_id TEXT NOT NULL,
    host_id TEXT NOT NULL,
    timestamp_utc TEXT NOT NULL,
    sample_window_seconds REAL NOT NULL,
    read_bytes_per_sec REAL,
    write_bytes_per_sec REAL,
    read_iops REAL,
    write_iops REAL,
    avg_read_latency_ms REAL,
    avg_write_latency_ms REAL,
    source TEXT NOT NULL,
    FOREIGN KEY (device_id) REFERENCES devices(device_id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_device_metrics_lookup ON device_metrics(device_id, timestamp_utc);
```

### Table: `process_metrics`
Telemetry samples for running application processes.
```sql
CREATE TABLE IF NOT EXISTS process_metrics (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    process_instance_id TEXT NOT NULL,  -- f"{pid}_{start_time_utc}"
    host_id TEXT NOT NULL,
    pid INTEGER NOT NULL,
    start_time_utc TEXT,
    process_name TEXT,
    timestamp_utc TEXT NOT NULL,
    sample_window_seconds REAL NOT NULL,
    read_bytes_per_sec REAL,
    write_bytes_per_sec REAL,
    attributed_device_id TEXT
);
CREATE INDEX IF NOT EXISTS idx_process_metrics_lookup ON process_metrics(process_instance_id, timestamp_utc);
```

### Table: `file_activity`
Fine-grained telemetry observation windows for individual files.
```sql
CREATE TABLE IF NOT EXISTS file_activity (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    host_id TEXT NOT NULL,
    file_id TEXT,
    path TEXT,
    device_id TEXT,
    window_start_utc TEXT NOT NULL,
    window_end_utc TEXT NOT NULL,
    read_bytes INTEGER,
    write_bytes INTEGER,
    read_ops INTEGER,
    write_ops INTEGER,
    file_size_bytes INTEGER,
    read_average_gap REAL,
    write_average_gap REAL,
    source TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_file_activity_window ON file_activity(window_start_utc, window_end_utc);
CREATE INDEX IF NOT EXISTS idx_file_activity_path ON file_activity(path, window_start_utc);
CREATE INDEX IF NOT EXISTS idx_file_activity_device ON file_activity(device_id, window_start_utc);
```

### Table: `file_subscriptions`
Persistent registry of directories and files monitored across reboots.
```sql
CREATE TABLE IF NOT EXISTS file_subscriptions (
    subscription_id TEXT PRIMARY KEY,
    host_id TEXT NOT NULL,
    path TEXT NOT NULL UNIQUE,
    target_type TEXT NOT NULL,          -- 'file' or 'folder'
    status TEXT NOT NULL DEFAULT 'active', -- 'active', 'paused', 'removed'
    created_at_utc TEXT NOT NULL,
    updated_at_utc TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_file_subscriptions_status ON file_subscriptions(status);
```

### Table: `file_move_records`
Persistent log of file migration jobs, caller-supplied byte counts and lifecycle states.
```sql
CREATE TABLE IF NOT EXISTS file_move_records (
    move_id TEXT PRIMARY KEY,
    recommendation_id TEXT,
    host_id TEXT NOT NULL,
    file_id TEXT,
    source_path TEXT NOT NULL,
    target_path TEXT NOT NULL,
    source_device_id TEXT,
    target_device_id TEXT,
    bytes_total INTEGER,
    bytes_moved INTEGER DEFAULT 0,
    status TEXT NOT NULL DEFAULT 'pending', -- 'pending', 'approved', 'in_progress', 'completed', 'failed', 'cancelled'
    error_message TEXT,
    started_at_utc TEXT,
    completed_at_utc TEXT,
    updated_at_utc TEXT NOT NULL,
    FOREIGN KEY (recommendation_id) REFERENCES recommendations(recommendation_id) ON DELETE SET NULL
);
CREATE INDEX IF NOT EXISTS idx_file_move_records_status ON file_move_records(status);
```

### Table: `recommendations`
Stores generated optimization advice from ALGO-01 and ALGO-02.
```sql
CREATE TABLE IF NOT EXISTS recommendations (
    recommendation_id TEXT PRIMARY KEY,
    mode TEXT NOT NULL,                 -- 'raid0' or 'ssd_caching'
    action TEXT NOT NULL,               -- 'move', 'cache', 'evict', 'none'
    file_id TEXT,
    source_device_id TEXT,
    target_device_id TEXT,
    reason TEXT NOT NULL,
    created_at_utc TEXT NOT NULL,
    requires_approval INTEGER NOT NULL DEFAULT 1,
    estimated_benefit TEXT,             -- JSON object
    constraints TEXT                    -- JSON list
);
```

### Table: `app_settings`
Arbitrary JSON key-value store for application configuration.
```sql
CREATE TABLE IF NOT EXISTS app_settings (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL,
    updated_at_utc TEXT NOT NULL
);
```

## 4. Maintenance and Operations Guide

### Database File Location
The database is initialized by default at `wsd.db` in the working directory (or a custom path passed to `SQLiteHistoryRepository(db_path=...)`).

### WAL Checkpointing
In WAL mode, writes accumulate in `wsd.db-wal` before being transferred to the main `wsd.db` file. SQLite automatically checkpoints when the WAL reaches 1000 pages. 
For clean backup or shutdown, applications can trigger an explicit checkpoint:
```python
with repo._get_connection() as conn:
    conn.execute("PRAGMA wal_checkpoint(TRUNCATE);")
```

### Data Retention and Pruning
High-frequency telemetry (`device_metrics`, `process_metrics`, and `file_activity`) accumulates rapidly over days of continuous monitoring.
- **Recommended Policy:** Retention window of 7 days for raw telemetry.
- **Pruning Query Example:**
```sql
DELETE FROM device_metrics WHERE timestamp_utc < datetime('now', '-7 days');
DELETE FROM process_metrics WHERE timestamp_utc < datetime('now', '-7 days');
DELETE FROM file_activity WHERE window_end_utc < datetime('now', '-7 days');
```
Pruning preserves persistent entity records (`devices`, `file_subscriptions`, and `file_move_records`).

### Backup and Restore
Because WAL mode allows concurrent readers, a live database can be safely copied using SQLite's backup API or standard shell commands after executing `PRAGMA wal_checkpoint(PASSIVE);`.

## 5. API Reference

All database access occurs through `SQLiteHistoryRepository` (or the Core wrapper `DataBaseAdaptor`). All inputs and outputs use standard Python types (`dict`, `list`, `str`, `int`, `float`, `None`). No SQL syntax or database handles cross component boundaries.

### Hardware & Telemetry Ingestion

#### `upsert_devices(devices: List[Dict[str, Any]]) -> None`
Ingests or updates known storage devices. On conflict on `device_id`, updates capacity, free space, availability, mount points, and `last_seen_utc`.

#### `ingest_device_metrics(samples: List[Dict[str, Any]]) -> None`
Inserts a batch of drive telemetry samples using parameterized transactions (`executemany`).

#### `ingest_process_metrics(samples: List[Dict[str, Any]]) -> None`
Inserts application I/O samples. Automatically computes `process_instance_id` as `f"{pid}_{start_time_utc}"` if not explicitly supplied.

#### `ingest_file_activity(samples: List[Dict[str, Any]]) -> None`
Inserts high-resolution file observation windows. Safely ingests `read_average_gap`, `write_average_gap`, and `file_size_bytes`.

---

### Historical Queries

#### `query_device_history(device_ids: List[str], start_utc: str, end_utc: str, bucket_seconds: Optional[int] = None) -> List[Dict[str, Any]]`
Queries device metrics within `[start_utc, end_utc]`.
- If `bucket_seconds=None` or `0`: Returns raw time-series records ordered chronologically (`ASC`).
- If `bucket_seconds > 0`: Aggregates samples into time buckets, returning `avg_read_bytes_per_sec`, `avg_write_bytes_per_sec`, `avg_read_iops`, `avg_write_iops`, and `sample_count`.
- Returns `[]` if no devices are provided or no data matches. Never fabricates zero values.

#### `query_process_history(process_instance_ids: List[str], start_utc: str, end_utc: str, bucket_seconds: Optional[int] = None) -> List[Dict[str, Any]]`
Queries historical metrics for specific application instances (US-02). Supports both raw samples and bucketed time intervals.

#### `query_file_activity_windows(start_utc: str, end_utc: str, path: Optional[str] = None, device_ids: Optional[List[str]] = None, limit: int = 5000) -> List[Dict[str, Any]]`
Queries file activity observation windows.
- **Ordering:** Ordered by `window_start_utc DESC` (newest records first) to feed prediction algorithms with the most relevant telemetry.
- **Outputs:** Includes `read_average_gap` and `write_average_gap`.

#### `query_file_heat(start_utc: str, end_utc: str, limit: int = 100, device_ids: Optional[List[str]] = None, path: Optional[str] = None) -> List[Dict[str, Any]]`
Aggregates file heat grouped by file identity (`COALESCE(path, file_id)`).
- **Ranking:** Ordered by `total_bytes DESC LIMIT ?`.
- **Outputs:** `total_read_bytes`, `total_write_bytes`, `total_bytes`, `total_read_ops`, `total_write_ops`, `sample_count`, `avg_read_average_gap`, and `avg_write_average_gap`.
- Supports exact path lookups via the `path` parameter.

---

### Subscription and Migration Management

#### `upsert_file_subscription(sub: Dict[str, Any]) -> None`
Registers or updates a watched file or directory path. On conflict on `path`, updates `target_type`, `status`, and `updated_at_utc`.

#### `list_file_subscriptions(status: Optional[str] = None) -> List[Dict[str, Any]]`
Returns registered subscriptions, optionally filtered by status (`'active'`, `'paused'`, `'removed'`).

#### `save_file_move_record(record: Dict[str, Any]) -> None`
Creates or updates a file migration record. On conflict on `move_id`, updates `bytes_moved`, `status`, `error_message`, and timestamps.

#### `get_incomplete_file_moves() -> List[Dict[str, Any]]`
Returns all moves with `status IN ('approved', 'in_progress')` ordered by `updated_at_utc ASC`. This is a database query; CORE does not currently call it on startup or resume the returned moves.

#### `list_file_move_records(status: Optional[str] = None, limit: int = 100) -> List[Dict[str, Any]]`
Returns historical migration jobs, ordered by `updated_at_utc DESC`.

---

### Settings and Recommendations

#### `save_settings(settings: Dict[str, Any]) -> None` / `get_settings() -> Dict[str, Any]`
Saves and loads key-value application settings. Complex types (dictionaries, lists, booleans, floats) are serialized and deserialized via JSON.

#### `save_recommendations(items: List[Dict[str, Any]]) -> None` / `list_recommendations(mode: Optional[str] = None) -> List[Dict[str, Any]]`
Stores algorithm placement recommendations. Upserts on `recommendation_id`. Automatically serializes and deserializes JSON fields (`estimated_benefit`, `constraints`).

## 6. Non-Functional Requirements (NFRs)

- **Performance:** Ingestion queries use batched transactions (`executemany`) to support up to 500 samples per second. Targeted composite indexes ensure sub-10ms lookup times for time-bounded range queries across 24 hours of data.
- **Reliability and Fault Tolerance:** Write-Ahead Logging prevents database corruption during sudden power loss or process termination. Foreign key cascades keep relational state clean. Unfinished move records remain queryable after restart; transfer resume is not yet implemented in CORE.
- **Maintainability:** Full separation of SQL semantics from consumer modules. Core and Algorithm layers communicate via clean Python primitives without SQL dependencies.
- **Safety and Truthfulness:** Missing telemetry returns explicit empty collections `[]` or `None`. The database never invents zero measurements, baseline durations, or synthetic heat scores.

---

## 7. Current Limitations

1. **Pruning Daemon:** Automatic 7-day telemetry pruning is currently triggered manually or on schedule by CORE; the repository does not spawn its own background pruning thread.
2. **Dynamic Schema Migration:** Schema initialization uses `schema.sql`. Column additions (such as adding new gap metrics) on pre-existing non-volatile user databases require a lightweight SQLite migration script or rebuilding the database file.
